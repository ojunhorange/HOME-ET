# HOME:ET 산출식 명세

자취지수(①)와 적정 월세 상한(②)의 계산 방식, 상수, 코드 위치를 정리한 문서입니다.
모든 금액은 원, 모든 값은 **학기 중 한 달** 기준입니다(월 등교일 = 주당 등교일 × 4.3, 방학 미반영). 경로는 레포 루트 기준입니다.

> 계수는 팀 확정 전 초안입니다. 바뀐 점 요약은 [이전 식과 다른 점](#7-이전-식과-다른-점)에 있습니다.

---

## 1. 입력

| 기호 | 의미 | 필드 (`Commute` / `LivingCosts`) |
| --- | --- | --- |
| `T₁` | 본가→학교 편도 소요시간(분) | `oneWayMin` |
| `n` | 환승 횟수 | `transfers` |
| `h` | 배차 간격(분). 대기 여유 시간으로 하루 1회 반영. **현재는 입력 질문을 없애고 0으로 고정**(Google 경로 시간에 환승 대기가 포함됨) | `headwayMin` |
| `F` | 통학 왕복 교통비 | `roundTripFare` |
| `d` | 주당 등교일 | `daysPerWeek` |
| `w` | 1시간의 기준 시급. **입력 질문을 없애고 2026 최저임금 10,320원으로 고정**. 개인차는 가치관 배수가 반영(`myHourValue = w·(m_t + f·m_b)/m_m`, 3-6 참고) | `hourlyWage` |
| `R` | 월세 | `rent` |
| `M` | 관리비 | `mgmt` |
| `Lv` | 추가 생활비 | `living` |
| `I` | 이사·가구가전 등 초기 비용 (**중개보수 제외**) | `initialTotal` |
| `Dp` | 보증금 | `deposit` |
| `r` | 보증금 기회비용 연이율 | `annualRate` |
| `L` | 자취 시 하루 왕복 통학(분) | `compute()` 4번째 인자 |
| `F_L` | 자취 시 하루 왕복 교통비 | `compute()` 5번째 인자 |

## 3. 계산 순서 (`compute()`, `lib/calc.ts`)

### 3-1. 되찾는 시간

```
commuteDailyMin    = 2·T₁ + h
savedDailyMin      = max(0, commuteDailyMin − L)
D                  = d × 4.3                          // 월 등교일
ΔH                 = savedDailyMin / 60 × D           // 월 절약 시간
```

### 3-2. 시간·체력의 금액 가치

```
G_t          = ΔH × w
f            = min(0.5, 0.15 + 0.1·n)                 // fatigueCoef()
G_b          = ΔH × f × w
```

### 3-3. 자취 추가 비용

```
B              = 중개보수(Dp, R)                       // 3-7 참고
initialMonthly = (I + B) / 24
depositCost    = Dp × r / 12
savedFare      = max(0, F − F_L) × D
ΔC = R + M + Lv + initialMonthly + depositCost − savedFare
```

### 3-4. 가치관 조정값 → 배수

```
m_k = 1 + 0.25 · a_k        (a_k ∈ {−3 … +3}  →  m_k ∈ [0.25, 1.75])
```

- 세 조정값은 **서로 독립**입니다. 합을 맞추지 않으므로 하나를 바꿔도 나머지는 그대로입니다.
- 0이면 배수 1, 즉 "가치관 보정 없이 금액 그대로" 비교합니다.
- 배수가 0이 되지 않으므로(최소 0.25) 월세 상한은 항상 유한합니다.

### 3-5. 선형 자취지수

```
N = m_t·G_t + m_b·G_b − m_m·ΔC          // 가치관을 반영한 월 순이득(원)
S = G_t + G_b + |ΔC|                    // 정규화 기준. 가치관과 무관
index = clamp(50 + 50·N / S, 0, 100)
```

선형이라 지수를 항목별 점수의 합으로 그대로 쪼갤 수 있고, 리포트 점수 카드에 이렇게 보여 줍니다.

```
index = 50 + c_t + c_b + c_m
c_t = 50·m_t·G_t / S    c_b = 50·m_b·G_b / S    c_m = −50·m_m·ΔC / S
```

- **조작감**: 슬라이더 1칸이 움직이는 점수는 `50 × 0.25 × G_k / S`로 항상 같습니다(`pointsPerStep`). 슬라이더 위치에 따라 민감도가 달라지지 않습니다. 화면에 "한 칸에 ±x점"으로 보여 줍니다.
- **1점의 의미**: 1점 = 월 순이득 `S / 50`원. 같은 사람이라면 점수 차이가 그대로 금액 차이입니다.
- **이전 식과의 관계**: 모든 조정값이 0이면 `50 + 50(G − ΔC)/(G + ΔC) = 100·G/(G + ΔC)`로, 이전 비율식과 **같은 값**입니다. 이전 식은 가치관을 바꾸면 분모도 같이 움직여서 점수가 비선형으로 변했습니다.
- **판정**: `index ≥ 50 ⇔ N ≥ 0`이면 "자취 추천", 아니면 "다시 생각해 보기". 50 단일 기준입니다.
- 50·N/S가 ±50을 넘으면 0 또는 100에서 자릅니다. 점수 카드에 "(0~100으로 자름)"이 붙습니다.

### 3-6. 지불 의향과 1시간 비교

```
W            = (m_t·G_t + m_b·G_b) / m_m
myHourValue  = W / ΔH            (ΔH = 0 이면 0)     "내가 매기는 1시간의 가치"
             = w·(m_t + f·m_b) / m_m              // W = w·ΔH·(m_t + f·m_b)/m_m 이므로. w = 최저임금 고정
buyBackPrice = ΔC / ΔH           (ΔH = 0 이면 0)     "자취로 1시간을 되사는 가격"
```

`index ≥ 50 ⇔ N ≥ 0 ⇔ W ≥ ΔC ⇔ myHourValue ≥ buyBackPrice` 이므로 리포트의 두 막대 비교는 판정과 항상 일치합니다.

### 3-7. 중개보수 (주택 임대차, 서울시 조례 상한요율)

```
거래금액 X = Dp + 100·R          (단, 이 값이 5천만 원 미만이면 X = Dp + 70·R)   // 공인중개사법 시행규칙 제20조 ⑤
B = min(한도, X × 요율)
```

| 거래금액 | 상한요율 | 한도 |
| --- | --- | --- |
| 5천만 원 미만 | 0.5% | 20만 원 |
| 5천만 ~ 1억 원 미만 | 0.4% | 30만 원 |
| 1억 ~ 6억 원 미만 | 0.3% | 없음 |
| 6억 ~ 12억 원 미만 | 0.4% | 없음 |
| 12억 ~ 15억 원 미만 | 0.5% | 없음 |
| 15억 원 이상 | 0.6% | 없음 |

- `brokerageFee()` (`lib/calc.ts`). 상한이므로 실제로는 협의로 더 낮을 수 있고, 부가세는 별도입니다.
- 예: 보증금 1,000만 / 월세 55만 → X = 6,500만 → 0.4% = **26만 원**. 보증금 500만 / 월세 40만 → 100배 합이 4,500만이라 70배로 3,300만 → 0.5% = 16.5만 원.
- 오피스텔(전용 85㎡ 이하 등)은 0.4% 단일 요율이라 다릅니다. 지금은 주택 기준만 씁니다.
- ③ D-day의 "잔금·입주일" 할 일과 용어 카드("중개보수")에도 이 값을 보여 줍니다(`lib/dday.ts`).

### 3-8. 적정 월세 상한 (②)

`index = 50`, 즉 `ΔC(R) = W`가 되는 `R`을 구합니다. 중개보수가 `R`에 따라 구간별로 달라져서 식 하나로는 안 풀리고, 이분법으로 풉니다(`solveRentCap()`).

```
목표값  T = W − M − Lv − I/24 − depositCost + savedFare
R + B(Dp, R)/24 = T  를 R에 대해 푼다           // 좌변은 R에 대해 항상 증가
T ≤ B(Dp, 0)/24 이면 상한 ≤ 0 ("어떤 월세도 손해")
```

화면 표시는 `max(0, rentCap)`입니다. 내역의 "초기 비용"은 **상한 월세에서의** 중개보수로 다시 계산해 항목 합이 상한과 맞게 했습니다.

**② 화면에서의 호출** (`rentModel`, `lib/view-models.ts`):

```ts
compute(state.commute, { ...state.costs, rent: region.rentMedian, mgmt: region.mgmtMedian },
        state.adj, region.oneWayMin * 2, regionFare(region))
```

- `L = 지역→학교 편도 × 2`. 자취 쪽에는 배차 대기 시간을 넣지 않습니다.
- `F_L = regionFare(region)`, `M`은 선택 지역의 관리비 중앙값입니다.
- 지역 월세 중앙값은 비교 문구에만 쓰고, 상한은 `L`, `F_L`, `M`을 통해서만 지역의 영향을 받습니다.

### 3-9. 보증금 ↔ 월세 환산

```
환산 월세 = R + Dp × r / 12           // effectiveRent()
```

보증금·월세 조합이 다른 방은 환산 월세가 작은 쪽이 쌉니다. ② 화면에는 "보증금을 1,000만 원 더 넣으면 상한이 약 x만 원 내려가요"를 함께 보여 줍니다. 값은 보증금 +1,000만으로 상한을 한 번 더 계산한 차이라서 중개보수 변화까지 들어갑니다(대략 `1,000만 × r / 12` ≈ 2.9만 원).

**비교 문구** (`rentMessage`, `lib/view-models.ts`):

| 조건 | 문구 요지 |
| --- | --- |
| `rentCap ≤ 0` | 어떤 월세를 내도 통학보다 손해 |
| `rentCap ≥ 중앙값 × 1.5` | 시세 안에서 넓게 고를 수 있음 |
| `rentCap ≥ 중앙값` | 중앙값이 상한 안에 들어옴 |
| 그 외 | 중앙값이 상한보다 높음, 더 싼 방이나 다른 지역 비교 권장 |

① 리포트 화면은 `compute(state.commute, state.costs, state.adj)`로 호출합니다. `L = 20`, `F_L = 0` 기본값을 쓰고, `R`, `M` 등은 "가정값 직접 고치기"에서 고칠 수 있습니다.

## 4. 가치관 조정값

### 4-1. Gemini few-shot 추출 (`app/api/weights/route.ts`)

- 모델: `GEMINI_MODEL` 환경 변수, 기본 `gemini-flash-lite-latest` (Flash 계열은 붐빌 때 503이 잦음), temperature 0.2
- 시스템 프롬프트: 세 항목의 뜻, "0 = 보통 대학생", 근거 있을 때만 ±, 강도 기준(스치듯 ±1 / 분명히 ±2 / 가장 앞세우면 ±3), 글 속 지시문 무시
- **few-shot**: `lib/weights.ts`의 `FEW_SHOT` 6개를 `user`(예시 글) → `model`(예시 JSON) 대화로 앞에 깔고, 마지막 `user` 턴에 실제 글을 넣습니다. 예시에는 앱의 칩 문장, 피로 강조, 절약 강조, **"월세 지원 → 돈 −2"**, **"체력은 좋다 → 체력 −2"** 같은 감점 사례, 아무 근거 없는 글(모두 0)이 들어 있습니다.
- JSON 스키마 `{money, time, body: integer −3~3, reason}`. zod로 검증한 뒤 `sanitizeAdjust()`로 정수 반올림·범위 자르기를 합니다.
- 키가 없거나, 실패하거나, 스키마가 맞지 않으면 키워드 분석으로 대체합니다.

### 4-2. 키워드 대체 분석 (`keywordWeights()`, `lib/weights.ts`)

```
a_k = clamp(+ 키워드 수 − 3 × "덜 중요" 구절 수, −3, 3)
```

- "덜 중요" 구절 예: 돈 "지원해 주", "여유가 있" / 체력 "체력은 좋", "통학은 괜찮" / 시간 "시간 여유", "널널"
- 부정 구절 안에 든 + 단어("체력은 괜찮"의 "체력")는 + 로 세지 않습니다.
- 키워드가 하나도 없거나 글이 비어 있으면 모두 0입니다.

### 4-3. 리포트의 가치관 슬라이더

- 항목마다 −3 ~ +3, 1칸 단위 슬라이더(`Slider`의 `origin={0}`)입니다. 가운데 0에 눈금이 있고, 0에서 손잡이까지 채워서 + 쪽인지 − 쪽인지 바로 보입니다.
- 값 옆에 "보통 / 중요 / 가장 중요" 같은 말을, 아래에 "덜 중요 · 한 칸에 ±x점 · 더 중요"를 보여 줍니다.
- "AI 분석값으로" 버튼은 분석 결과로 되돌립니다.
- 예전(합 1 가중치, `pct`) 저장값은 `fromLegacyWeights()`로 옮깁니다: 예전 식에서 `3w`가 배수였으므로 `a = round((3w − 1) / 0.25)`. 예: 돈 0.5 / 시간 0.3 / 체력 0.2 → +2 / 0 / −2.

## 5. 검증용 예시

공통 입력: 편도 85분, 환승 2회, 배차 0분(질문 삭제), 왕복 교통비 4,500원, 주 4일, 시급 10,320원, 월세 55만, 관리비 7만, 생활비 15만, 이사·가구가전 54만, 보증금 1,000만(3.5%)

| 중간값 | 값 |
| --- | --- |
| savedDailyMin | 170 + 0 − 20 = 150분 |
| D | 4 × 4.3 = 17.2일 |
| ΔH | 2.5 × 17.2 = 43시간 |
| G_t | 443,760 (44.4만) |
| f / G_b | 0.35 / 155,316 (15.5만) |
| 중개보수 B | 6,500만 × 0.4% = 260,000 |
| initialMonthly | (540,000 + 260,000) / 24 = 33,333 |
| depositCost | 29,167 |
| savedFare | 77,400 |
| ΔC | 755,100 (75.5만) |
| S | 443,760 + 155,316 + 755,100 = 1,354,176 (1점 ≈ 2.7만 원) |

**조정값 모두 0** → 지수 44.24 (이전 비율식 `100·G/(G+ΔC)`와 같음)

**① 리포트, 조정값 돈 +1 / 시간 0 / 체력 −1 (배수 1.25 / 1.00 / 0.75, L = 20)**

| 출력 | 값 |
| --- | --- |
| c_t / c_b / c_m | +16.38 / +4.30 / −34.85 |
| 자취지수 | 50 + 16.38 + 4.30 − 34.85 = 35.8 → 다시 생각해 보기 |
| 한 칸 점수 (돈 / 시간 / 체력) | −7.0 / +4.1 / +1.4 |
| W | (443,760 + 0.75·155,316) / 1.25 = 448,198 |
| 1시간 가치 / 되사는 가격 | ≈ 10,423원 / 17,560원 |

**② 월세 상한, 조정값 돈 −1 / 시간 +2 / 체력 +1 (배수 0.75 / 1.5 / 1.25), 안암동(도보 10분 → L = 20, F_L = 0)**

| 출력 | 값 |
| --- | --- |
| W | (1.5·443,760 + 1.25·155,316) / 0.75 = 1,146,380 (114.6만) |
| rentCap | 939,124 (93.9만). 이때 거래금액 1억 391만 → 0.3%로 중개보수 311,737 → 초기 비용 35,489 |
| 검산 | 1,146,380 − 70,000 − 150,000 − 35,489 − 29,167 + 77,400 = 939,124 |
| 보증금 +1,000만 | 상한 909,083 (약 3.0만 원 ↓) |

## 6. 기획서 초안과 다른 점

| 항목 | 기획서 초안 | 구현 | 이유 |
| --- | --- | --- | --- |
| 자취지수 | `100·E/(E+K)` (비율) | `50 + 50·N/S` (선형) | 가치관 조작에 따른 점수 변화가 일정하고, 항목별 점수로 쪼개짐 |
| 가중치 | 돈·시간·체력 합 1 | 0 기준 −3 ~ +3 조정값, 서로 독립 | 하나를 바꿔도 나머지가 안 움직여 직관적 |
| 통학 시간 | 왕복 시간 | `2·편도 + 배차 간격`(배차 간격은 현재 0 고정) | 프로토타입의 "여유 시간 포함". 지금은 기획서와 같음 |
| 피로 계수 f | `0.2 + 0.1·n` (≤ 0.5) | `0.15 + 0.1·n` (≤ 0.5) | 프로토타입 화면이 환승 2회에서 0.35 |
| 초기 비용 | 없음 | `(I + 중개보수) / 24` (기본 I = 54만, 기본 계약이면 합 80만) | 중개보수는 법정 상한식으로 계산 |
| 자취 지역 교통비 | 없음 | 버스·지하철 지역이면 `F_L = 3,000` 차감 | 걸어갈 수 없는 지역 보정 |

## 7. 이전 식과 다른 점

이 레포의 바로 이전 버전(비율식 + 합 1 가중치 슬라이더) 대비 바뀐 점입니다.

1. **수식 선형화**: `100·E/(E+K)` → `clamp(50 + 50·N/S)`. 조정값이 모두 0이면 두 식의 값이 같습니다.
2. **가중치 → 조정값**: 합 1 슬라이더(`pct`, `rebalance`) → 0 기준 ± 슬라이더(`adj`), 세 슬라이더가 서로 독립. 판정 경계(`N = 0`)와 월세 상한 구조(`ΔC = W`)는 그대로입니다.
3. **LLM few-shot**: 설명만 하던 프롬프트 → 예시 6쌍을 대화로 넣는 few-shot, 출력은 정수 조정값.
4. **중개보수**: 초기 비용 80만(중개보수 포함) → 54만 + 법정 상한식으로 계산한 중개보수. 기본 계약이면 합이 80만으로 같습니다. 예전 기본값 165만·80만으로 저장된 상태는 54만으로 옮깁니다.
5. **보증금 환산**: ② 화면에 보증금 1,000만 원당 상한 변화와 환산 월세 비교법을 보여 줍니다.

## 8. 알려진 한계 / 팀 확정 필요

- **조정값 범위·간격**: −3 ~ +3, 1칸 = 25%는 초안입니다. 모두 +3이면 "다 중요"가 아니라 "판단이 더 단호해짐"(50에서 더 멀어짐)이 됩니다.
- **항목별 민감도 차이**: 1칸 점수가 금액 크기에 비례해서, 보통 돈(ΔC가 큼)은 한 칸에 8점 안팎, 체력은 1점 안팎만 움직입니다. 금액 기준으로는 맞지만 체력 버튼이 약하게 느껴질 수 있습니다.
- **피로 계수**: 환승 횟수만 씁니다. 혼잡 시간대나 도보 시간은 반영하지 않습니다.
- **생활비·초기 비용·이율**: 기본값에 근거 자료가 없습니다.
- **중개보수**: 주택 기준 상한이고 부가세 미포함입니다. 오피스텔 요율, 실제 협의 금액은 반영하지 않습니다.
- **판정 기준**: 50 단일 기준입니다. 45~55 "애매함" 구간은 없습니다.
- **자취 쪽 통학 시간**: 배차 대기를 넣지 않아서 통학 쪽과 비대칭입니다.
- **`F_L`**: 3,000원 상수입니다. 실제 요금이나 환승 할인을 반영하지 않습니다.
- **통학 정보**: Google Routes API로 경로를 고르면 편도·환승·왕복 교통비가 채워지고, 사용자가 고칠 수 있습니다(`GOOGLE_MAPS_UI.md`). 광역버스·GTX 요금은 아직 반영하지 않습니다.
- **시세 데이터**: 6개 학교 × 3개 동의 예시 값입니다. 국토부 전월세 실거래가 가공 전입니다.
- **극단값**: ΔH = 0이고 ΔC > 0이면 지수는 0입니다. S = 0(이득도 비용도 0)이면 50입니다.
