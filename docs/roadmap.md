# 추후 확장 계획

지금 버전에서 일부러 미뤄 둔 기능과 결정이 필요한 항목을 모아 둔 문서예요. 구현하면 이 문서에서 지우고, 관련 설명은 해당 문서(`metrics.md`, `GOOGLE_MAPS_UI.md`)로 옮겨 주세요.

## 1. 동별 월세 시세 수집 (국토부 전월세 실거래가)

**현재:** `lib/data.ts`에 학교마다 동 3곳의 월세·관리비 중앙값이 **예시 데이터**로 들어 있고, 동 목록과 학교까지 시간도 사람이 직접 골랐어요.

**계획:** 공공데이터포털의 국토교통부 전월세 실거래가 API로 **모든 동**의 시세를 수집해요.

**저장 방식: JSON (DB 아님)**
- 앱에 필요한 건 동마다 한 줄(중앙값, 거래 건수, 좌표)이에요. 서울 법정동 약 470개, 수도권으로 넓혀도 수천 줄(수백 KB)이에요.
- 실거래가는 월 단위로 쌓이는 데이터라 한 달에 한 번 다시 만들면 충분해요.
- DB 서버, 키 관리, 장애 대응이 필요 없고, 시세 변화가 git diff로 남아요.

**구조**
1. 수집 스크립트(예: `scripts/build-rent.ts`)가 원본 거래를 받아요. 원본은 앱에 넣지 않아요.
2. 동별로 집계해요: 월세·관리비·보증금 중앙값, 거래 건수, 기준 기간
   - 대상: 단독·다가구, 연립·다세대, 오피스텔의 월세 거래
3. 동 좌표는 스크립트에서 한 번만 지오코딩해서 같이 저장해요. 지도 알약 마커에 필요해요.
4. 결과를 `data/rent-by-dong.json`으로 저장하고 커밋해요.
5. 앱은 서버에서 이 파일을 읽어 **고른 학교 주변 동만** 화면에 보내요. 전체 파일을 브라우저로 보내지 않아요.

**결정 필요**
- 학교마다 어떤 동을 후보로 보여 줄지 정하는 규칙. 예: 학교에서 가까운 순으로 N곳, 또는 학교까지 대중교통 30분 이내
- 학교까지 시간(`oneWayMin`, `mode`)을 Routes API로 계산해 JSON에 함께 저장할지
- 거래 건수가 적은 동(예: 최근 1년 10건 미만)의 처리: 숨기기 / "참고용" 표시 / 인접 동과 합치기
- 집계 기간(최근 6개월 / 12개월)과 갱신 주기

**DB로 넘어가야 하는 경우**
- 재배포 없이 자동 갱신이 필요할 때(예: 매일 수집)
- 원본 거래를 조건별로 조회해야 할 때(면적, 건물 유형, 기간 필터)
- 로그인 사용자의 리포트·일정을 저장할 때

이때도 집계 결과만 올리면 되고, Firestore 같은 서버 없는 DB면 충분해요.

## 2. 통학 경로·요금 정확도

- **광역버스·GTX 요금:** 지금은 거리 기반 수도권 통합 요금(`lib/calc.ts`의 `metroFare`)만 써서 광역버스·GTX 경로는 요금이 실제보다 낮게 나와요. 탈것 종류별 요금 규칙을 추가해야 해요.
- **배차 간격:** 입력 질문을 없애고 0으로 고정했어요(`docs/metrics.md`). 첫 차 대기 시간을 다시 반영하려면 경로의 첫 탈것 종류로 추정하는 방법이 있어요(예: 지하철 5~10분, 버스 10~15분).
- **경로 정렬:** 지금은 시간순이에요. 시간이 비슷하면(예: 5분 이내) 환승이 적은 경로를 먼저 보여 줄지 정해야 해요.
- **기차 통학:** 일반열차·KTX가 섞인 경로는 후보에서 빠져요. 기차로 통학하는 학생을 위해 별도 선택지로 보여 줄지 정해야 해요.

## 3. 지도

- **Map ID:** 지금은 Google 데모 ID(`DEMO_MAP_ID`)예요. Cloud 콘솔에서 프로젝트용 Map ID를 만들고, 서비스 색에 맞는 지도 스타일을 연결해요.
- **학교 핀 색:** Google 핀이 CSS 변수를 못 읽어서 accent 색 값을 코드에 직접 넣었어요(`components/screens/rent-screen.tsx`). 토큰 색을 바꾸면 같이 바꿔야 해요.
- **모바일 알약 크기:** 알약의 누르는 영역이 작으니 모바일 사용성을 보고 키울지 정해요.

## 4. API 키와 운영

- Maps 키에 HTTP 리퍼러 제한과 API 제한을 걸어요(브라우저 키는 배포 도메인 + localhost만, 서버 키는 Routes API만).
- 개발 중 대화·문서에 노출된 키는 재발급해요.
- API 라우트(`/api/commute`, `/api/weights`)에 호출 횟수 제한이 없어요. 공개 배포 전에 IP별 제한이나 Firebase App Check를 검토해요.
