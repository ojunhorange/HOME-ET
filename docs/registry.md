# 등기부등본 확인하기

계약 D-day 화면(④)에서 등기사항전부증명서 PDF를 올리면 소유자, 근저당, 압류·가처분·신탁 같은 **위험 신호**를 찾아 보여 줘요. "안전하다"고 판정하지 않고, 확인할 것만 알려 줘요.

```
PDF ─▶ /api/registry (app/api/registry/route.ts)
        ① 글자가 있는 PDF: unpdf로 글자와 위치(x·y)를 뽑아 표 칸으로 나눔 → lib/registry.ts   (키 필요 없음)
        ② Gemini 문서 이해(PDF 직접 입력 + JSON 스키마)로 기록을 뽑음  (GEMINI_API_KEY 필요)
        키가 있으면 ①과 ②를 동시에 돌려 소유자·살아 있는 권리·갑구 기록을 맞춰 봄 (교차 검증)
        글자가 없는 스캔본은 ②만 씀
     ─▶ 구조화된 사실: 소유자·지분, 을구 권리(근저당·전세권·임차권), 갑구 위험 기록, 말소 여부
     ─▶ 위험 신호 규칙 (lib/registry-rules.ts, AI 없이 고정 규칙)
     ─▶ 화면 (components/screens/registry-check.tsx): 신호 + 관련 조문 링크(법령 RAG 데이터) + 살아 있는 기록
```

**쓰는 Google 도구**: Gemini API 문서 이해(PDF 입력 + 구조화 출력), 관련 조문은 법령 RAG(`docs/law-rag.md`)와 같은 데이터

## 1. 읽기 (`lib/registry.ts`)

인터넷등기소 등본은 표 칸 위치가 정해져 있어서 x 좌표(pt)로 칸을 나눠요.

| 칸 | x 범위 |
| --- | --- |
| 순위번호 | < 75 |
| 등기목적 | 75 ~ 175 |
| 접수 | 175 ~ 255 |
| 등기원인 | 255 ~ 340 |
| 권리자 및 기타사항 | ≥ 340 |

- 순위번호 칸에 `10`, `10-1` 같은 숫자가 나오면 새 기록이 시작돼요. `(전 3)` 같은 옛 번호는 무시해요.
- "소유권에 관한 사항" → 갑구, "소유권 이외의 권리에 관한 사항" → 을구로 구역을 바꿔요. 머리글(주소 줄)·바닥글(열람일시)·"열람용" 워터마크는 빼요.
- **말소**: PDF에서는 빨간 줄로만 그어져서 글자로는 안 보여요. 그래서 `7번근저당권설정등기말소` 같은 말소 기록을 보고 7번과 그 부기(7-1, 7-2 …)를 말소로 표시해요. 두 줄로 나뉜 등기목적(`7번근저당권설정등` + `기말소`)은 붙여서 읽어요.
- **금액**: `금480,000,000원`, `금칠억팔천만원정`(한글 숫자) 모두 읽어요(`parseWon`).
- **부기**: `10-1 10번근저당권변경`은 10번의 채권최고액을, `10-2 10번근저당권이전`은 근저당권자를 바꿔요.
- **소유자**: 소유권 보존·이전으로 새로 정하고, `2번○○지분전부이전`처럼 지분이 넘어가면 분수로 계산해요(1/2 → 1/4 + 1/4).

## 2. 위험 신호 (`lib/registry-rules.ts`)

| 신호 | 수준 | 기준 |
| --- | --- | --- |
| 경매·압류·가압류·가처분·가등기·신탁 | 위험 | 갑구에 말소되지 않은 기록이 있음 |
| 환매특약 | 주의 | 갑구 |
| 임차권등기 | 위험 | 을구에 살아 있는 임차권 (이전 세입자가 보증금을 못 받았을 가능성) |
| 전세권 | 주의 | 을구에 살아 있는 전세권 (내 보증금보다 먼저 돌려받음) |
| 근저당 | 주의 / 위험 | 살아 있는 근저당. 시세를 넣으면 (채권최고액 합계 + 내 보증금) ÷ 시세가 **70% 이상이면 위험**, 60% 이상이면 주의 |
| 계약 상대 ≠ 소유자 | 위험 | 이름을 넣었을 때 등본의 소유자 중에 없음 |
| 공유 | 주의 | 소유자가 2명 이상 |
| 최근 소유권 변동 | 주의 | 90일 이내 |
| 오래된 등본 | 주의 | 열람일이 30일보다 오래됨 |
| 말소사항 빠짐 / 과거 근저당 말소 | 참고 | |
| 신호 없음 | 참고 | "찾은 위험 신호가 없어요" + 잔금 전날 다시 확인 안내 (안전하다고 말하지 않음) |

70% 기준은 흔히 쓰는 경험칙이에요. 팀에서 바꾸려면 `DEBT_RATIO_HIGH`만 고치면 돼요.

## 3. API: `POST /api/registry`

`multipart/form-data`: `file`(PDF, 4MB 이하: Vercel 요청 본문 한도 4.5MB), `deposit`(내 보증금), `price`(선택, 시세), `landlord`(선택, 계약 상대 이름)

응답 `RegistryResult`: `source`("text" | "gemini"), `facts`(주소·소유자·권리·갑구 기록), `signals`, `laws`(신호에 붙은 조문 id → 이름·법제처 링크)

**교차 검증** (`compareFacts`): 두 결과가 다르면 맨 위에 "두 방식으로 읽은 결과가 달라요" 주의 신호를 띄우고, 다른 곳(소유자·지분, 을구 n번, 갑구 n번)을 알려 줘요. 판단은 칸 위치로 읽은 ①을 우선으로 써요. 같으면 화면에 "두 방식으로 읽어 결과가 일치했어요"라고 보여 줘요.

**말소는 말소 기록으로만 판단해요.** 실제 등본으로 시험해 보니 Gemini(`gemini-flash-lite-latest`)가 기록 25건과 소유자·금액은 텍스트 판독과 똑같이 읽었지만(약 10초), 빨간 줄은 실제로 그어진 6건을 하나도 못 잡고 줄이 없는 1건을 말소로 봤어요. 살아 있는 근저당을 말소로 잘못 보면 위험 신호가 숨겨지니까, Gemini에는 말소 여부를 묻지 않고 두 방식 모두 "N번…말소" 기록으로 판단해요.

## 4. 개인정보

- 등본에는 소유자 이름·주소·생년월일이 있어요. **파일과 내용은 저장하지도, 로그로 남기지도 않아요.** 오류 로그에도 등본 내용을 넣지 않아요.
- 계약 상대 이름과 시세는 화면 상태로만 두고 localStorage·Firestore에 저장하지 않아요.
- **이름·주소 가리기**(기본 켜짐): 결과 화면에서 사람 이름(소유자·개인 권리자)을 "유○○"처럼, 주소를 동·읍·면까지만 보여 줘요. 발표·화면 공유용이고, 소유자 비교 같은 판단은 서버에서 원래 값으로 해요. 은행·회사 같은 기관 이름은 가리지 않아요. 버튼을 누르면 원래대로 보여요.
- 테스트용 실제 등본은 레포에 넣지 마세요.

## 5. 검증 / 한계

- 실제 등본(집합건물, 말소사항 포함, 7쪽)으로 확인: 공유자 2명 지분 1/2씩(상속으로 1/4 + 1/4), 근저당 6건·전세권 1건 모두 말소, 부기로 바뀐 채권최고액·근저당권자, 한글 금액까지 맞게 읽음.
- 살아 있는 근저당·가압류·최근 이전이 있는 가짜 데이터로 규칙 확인: 가압류 → 위험, 빚 + 보증금 73% → 위험.
- Gemini 문서 이해: 같은 등본에서 기록 25건·소유자·금액이 텍스트 판독과 일치(교차 검증 통과).
- **아직 못 해 본 것**: 글자 없는 스캔본(Gemini 단독 경로), 건물(다가구)·토지 등본, 근저당이 살아 있는 실제 등본, 공동담보목록이 붙은 등본, 브라우저 화면.
- 칸 위치는 인터넷등기소 형식에 맞췄어요. 형식이 다른 PDF는 ②(Gemini)로 넘어가게 하거나 칸 경계를 고쳐야 해요.
- 신탁은 신탁원부를 따로 떼어 봐야 정확해요. 이 기능은 "신탁된 집"이라는 신호까지만 알려 줘요.
